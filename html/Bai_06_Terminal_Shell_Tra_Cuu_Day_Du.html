Mở đầu — Tại sao bài học này quan trọng?

Terminal, shell và cách tra cứu là nền tảng để hiểu ai đang xử lý lệnh, xử lý vào thời điểm nào và chương trình thực sự nhận được những argument gì. Hai dòng gần giống nhau có thể cho kết quả rất khác nhau:

rm -rf "$DIR"
rm -rf $DIR

Một ví dụ khác là sudo echo 1 > /sys/some-device/control có thể báo Permission denied dù có sudo. Để hiểu nguyên nhân, cần phân biệt terminal, shell, chương trình ngoài và kernel.

Phần I — Khi bạn gõ một lệnh, điều gì xảy ra?

Xét lệnh:

ls -l /etc

Terminal cung cấp giao diện nhập/xuất; shell đọc và phân tích lệnh, thực hiện expansion và redirect; chương trình ls xử lý -l và /etc; kernel cung cấp system call.

Phần II — Terminal và Shell

Terminal là giao diện giúp người dùng nhập và nhận dữ liệu dạng ký tự. Các terminal emulator gồm GNOME Terminal, Konsole, Windows Terminal, xterm, Alacritty. Terminal không cần hiểu ls có nghĩa gì.

Shell là chương trình đọc, phân tích và thực hiện câu lệnh hoặc chạy chương trình khác. Shell là chương trình user space, không phải kernel.

ShellĐặc điểm
bashPhổ biến, hỗ trợ scripting
shGiao diện shell truyền thống
dashNhẹ, thường dùng trên Debian/Ubuntu
zshTương tác phong phú
fishCú pháp và UX thân thiện
ashNhẹ, thường dùng trong BusyBox
echo "$SHELL"
ps -p $$ -o pid,comm,args
printf "%s\n" "$BASH_VERSION"

$SHELL thường cho biết login shell, không chắc chắn là shell hiện tại. Bash có thể chạy interactive hoặc non-interactive.

#!/usr/bin/env bash
echo "Starting application"
./motor_controller

Liên hệ Embedded Linux: Khi SSH vào board, terminal vẫn ở máy local, còn shell và command chạy trên board. SSH không tự động đồng bộ filesystem.

Phần III — Shell phân tích câu lệnh

Trong ls -l /etc, ls là command, -l là option của ls và /etc là operand. Shell không cần hiểu ngữ nghĩa của -l; ý nghĩa do từng chương trình quyết định.

BướcCông việc
1. ĐọcNhận lệnh từ terminal/script
2. ParseNhận biết quote, toán tử, command
3. ExpansionBiến, substitution, glob...
4. Word splittingTách kết quả chưa quote khi áp dụng
5. RedirectThiết lập file descriptor
6. ExecuteChạy builtin, function, executable

Đây là sơ đồ sư phạm; Bash có thứ tự expansion chi tiết và các trường hợp đặc biệt. Ví dụ:

name="Linux roadmap"
printf "<%s>\n" $name

Sau expansion và splitting, printf thường nhận hai argument dữ liệu: Linux và roadmap.

Phần IV — Quoting

Single quote giữ nội dung literal; double quote vẫn cho phép thay biến và command substitution, nhưng bảo vệ ranh giới argument khỏi word splitting và globbing thông thường.

name='Linux roadmap'
printf '<%s>\n' "$name"
printf '<%s>\n' $name
printf '<%s>\n' '$name'
Cách viếtArgument dữ liệuOutput
"$name"1<Linux roadmap>
$namethường 2<Linux> và <roadmap>
'$name'1<$name>

Hãy thay đổi cách quote trong mô phỏng:

Globbing và dấu *

Shell mở rộng wildcard thành tên file trước khi chương trình nhận argument. Dấu sao trong single quote là literal. Ví dụ thư mục có main.c, motor.c và config.txt:

printf '<%s>\n' *
printf '<%s>\n' '*'
pattern='*.c'
printf '<%s>\n' $pattern
printf '<%s>\n' "$pattern"

Globbing phụ thuộc nội dung thư mục, locale và cấu hình shell. Không quote một biến có wildcard có thể biến một argument thành nhiều argument.

Phần V — Các loại expansion

Command substitution bỏ các newline cuối; biến Bash không chứa byte NUL. Arithmetic expansion là số nguyên, nên 5/2 cho kết quả 2. Brace expansion không cần file tồn tại, khác globbing.

Phần VI — Word splitting, IFS và tên file

IFS (Internal Field Separator) mặc định thường gồm space, tab và newline. Word splitting chỉ xảy ra trong các ngữ cảnh expansion cụ thể, không phải mọi khoảng trắng đều bị tách.

value="one two three"
printf "<%s>\n" $value
printf "<%s>\n" "$value"
printf "<%s>\n" hello\ world

Không dùng for file in $(ls) để duyệt file, vì tên chứa khoảng trắng hoặc newline sẽ bị xử lý sai.

for file in *; do
    [ -e "$file" ] || [ -L "$file" ] || continue
    printf "%s\n" "$file"
done

find . -type f -print0 |
while IFS= read -r -d "" file; do
    printf "%s\n" "$file"
done

Tên file Linux không thể chứa byte NUL, vì thế định dạng phân tách NUL an toàn cho tên file tùy ý.

Phần VII — Option, argument và dấu --

Tên file bắt đầu bằng dấu trừ có thể bị hiểu là option. Nhiều chương trình hỗ trợ -- để kết thúc việc phân tích option; cũng có thể thêm ./ vào đầu pathname.

cat -- -report.txt
cat ./-report.txt

Dấu -- thường là quy ước của chương trình nhận argument, không phải shell tự loại bỏ dấu này cho mọi external command.

Phần VIII — PATH: Linux tìm chương trình ở đâu?

PATH là danh sách thư mục mà shell tìm executable theo thứ tự khi cần phân giải command không chứa dấu /.

printf "%s\n" "$PATH"
# Ví dụ: /usr/local/bin:/usr/bin:/bin

Nếu có /usr/local/bin/python3 và /usr/bin/python3, thứ tự PATH có thể quyết định chương trình được chọn. Nhưng alias, function, builtin và command hashing cũng ảnh hưởng tới lookup.

Gõ: myapp
↓
/usr/local/bin — không thấy
↓
/usr/bin — tìm thấy
↓
Chạy executable

Vì sao ./program khác program? Tên không có / thường được tìm theo PATH khi cần external command; ./program là pathname trực tiếp. Thư mục hiện tại thường không có trong PATH để hạn chế chạy nhầm chương trình độc hại.

pwd
./motor_controller
../motor_controller
/home/user/linux-lab/motor_controller
type -a ls
command -v ls
hash
hash -r

which có thể không phản ánh đầy đủ alias/function của shell. Ưu tiên type -a và command -v.

mkdir -p "$HOME/linux-lab/bin"
cat > "$HOME/linux-lab/bin/hello-linux" <<'EOF'
#!/usr/bin/env bash
printf "Hello from Linux lab!\n"
EOF
chmod u+x "$HOME/linux-lab/bin/hello-linux"
"$HOME/linux-lab/bin/hello-linux"
export PATH="$HOME/linux-lab/bin:$PATH"
hello-linux

Không thay toàn bộ PATH bằng một thư mục mới, vì các command hệ thống có thể không còn được tìm thấy.

Phần X — Tại sao cd phải là builtin?

Working directory là trạng thái của tiến trình. Tiến trình con gọi chdir không thể tự thay đổi working directory của tiến trình cha.

Shell cha — cwd=/home/user
↓ fork()
Tiến trình con — chdir("/tmp")
↓ kết thúc
Shell cha vẫn cwd=/home/user
#include <stdio.h>
#include <unistd.h>
int main(void) {
    if (chdir("/tmp") != 0) { perror("chdir"); return 1; }
    puts("Changed directory in child process");
    return 0;
}
gcc test_cd.c -o test_cd
./test_cd
pwd
(cd /tmp; pwd)
pwd

Dấu ngoặc tròn tạo ngữ cảnh subshell; cd trong đó không đổi cwd của shell bên ngoài. Function thông thường gọi cd trực tiếp có thể thay đổi cwd shell hiện tại.

Phần XI — Biến Shell và Environment

Biến shell chỉ tồn tại trong shell hiện tại, trừ khi được export để truyền vào environment của chương trình con.

course=linux
bash -c 'printf "%s\n" "$course"'
export course
bash -c 'printf "%s\n" "$course"'
bash -c 'course=embedded; printf "child: %s\n" "$course"'
printf 'parent: %s\n' "$course"

Tiến trình con không thể tự cập nhật biến của shell cha. export chỉ đánh dấu biến cho quá trình khởi chạy command, không tự tạo tiến trình mới.

Shell cha: course=linux
↓
Shell con: không nhận được course
#include <stdio.h>
#include <stdlib.h>
int main(void) {
    const char *device = getenv("DEVICE");
    if (device != NULL) printf("Device: %s\n", device);
    return 0;
}

# Shell:
export DEVICE=/dev/ttyUSB0
./serial_monitor

Environment hữu ích để cấu hình ứng dụng nhưng không nên tùy tiện lưu secret vì có nguy cơ lộ qua log, dump hoặc công cụ quan sát.

Phần XII — Process, fork và execve

Với external foreground command, shell thường chuẩn bị expansion/redirect, tạo process con, process con exec chương trình và shell cha đợi kết thúc. Đây là mô hình điển hình, không phải quy tắc bất biến.

Bash
↓ fork()
Child process
↓ execve()
Executable ls (giữ PID của child)
↓ kết thúc
Shell cha tiếp tục

fork thường tận dụng copy-on-write. execve thay thế image chương trình trong process hiện tại, không tạo PID mới.

sleep 5
sleep 5 &
# Thử trong shell phụ, vì exec thay thế shell hiện tại:
bash -c "exec ls"

Dùng exec trực tiếp ở interactive shell có thể làm mất phiên shell đó.

Phần XVI — Debug lỗi command not found và permission denied

Khi gặp command not found, đừng vội cài lại package. Kiểm tra lookup, PATH, file, kiến trúc CPU, interpreter và loader.

type -a myapp
printf "%s\n" "$PATH"
ls -l ./myapp
./myapp
file ./myapp
readelf -h ./myapp
uname -m

Permission denied có thể do bit execute, quyền traverse trên thư mục cha, mount noexec hoặc chính sách SELinux/AppArmor.

ls -l ./myapp
chmod u+x ./myapp
findmnt -T ./myapp -o TARGET,OPTIONS
namei -l ./myapp

Không mặc định dùng sudo để che giấu lỗi permission.

Phần XIX — Các vấn đề tương tự trong thực tế

Vì sao printf thường phù hợp hơn echo cho dữ liệu tùy ý? echo có thể xử lý -n và backslash escape khác nhau theo implementation.

value='-n'
echo "$value"
printf '%s\n' "$value"

Vì sao source khác chạy script? source thực thi trong shell hiện tại; ./script.sh thường chạy trong process riêng.

source script.sh
. script.sh
./script.sh

Vì sao pipeline có thể làm mất cập nhật biến? Trong cấu hình Bash thông thường, phần tử pipeline có thể chạy trong subshell.

count=0
printf "a\nb\n" | while read -r line; do count=$((count+1)); done
printf "%s\n" "$count"

count=0
while IFS= read -r line; do count=$((count+1)); done < <(printf "a\nb\n")
printf "%s\n" "$count"

Bash có tùy chọn lastpipe và các điều kiện có thể thay đổi hành vi. Vì sao systemd chạy khác terminal? WorkingDirectory, PATH, environment, user/group, mount, quyền thiết bị, dependency và sandboxing có thể khác. Đừng giả định chương trình chạy thủ công được thì service cũng chạy được.

Phần XXIII — Tổng kết và dẫn sang Bài 07

Terminal không phải shell; shell không phải kernel. Dòng bạn gõ không nhất thiết là argv chương trình nhận. Quote biến để bảo vệ ranh giới argument.
