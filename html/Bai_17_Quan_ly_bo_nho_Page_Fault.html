1. Đặt vấn đề: Vì sao cần quản lý bộ nhớ?

Bài học chuyên sâu về Virtual Memory, MMU, TLB, page table, demand paging, page fault, COW, RSS/PSS, page cache, reclaim, swap, OOM, NUMA và phương pháp debug của kỹ sư Linux.

Trong bài 16, chúng ta đã tìm hiểu system call. Nhưng khi một chương trình yêu cầu 1 GB bộ nhớ, Linux lấy RAM từ đâu? Nó có cấp ngay 1 GB không? Để trả lời, ta phải phân biệt không gian địa chỉ ảo với các trang resident trong RAM.

Giả sử RAM 8 GiB, Chrome yêu cầu 3 GiB, VS Code 2 GiB, Python 4 GiB và OS 2 GiB. Tổng nhu cầu 11 GiB lớn hơn RAM, nhưng các ứng dụng vẫn có thể hoạt động vì bộ nhớ được reserve/map không đồng nghĩa resident. Hãy hình dung thư viện có nhiều sách trong kho nhưng số bàn đọc hữu hạn: đăng ký sách không đồng nghĩa đưa tất cả sách lên bàn.

Phản biện: Khi mọi ứng dụng thực sự chạm tất cả trang cùng lúc, chuyện gì xảy ra?

Kernel phải reclaim, swap khi phù hợp, hoặc xử lý tình trạng thiếu bộ nhớ.

2. Virtual Memory

Virtual Memory cung cấp mỗi process một không gian địa chỉ ảo, tách biệt địa chỉ RAM vật lý. CPU thường truy cập virtual address; MMU dịch sang physical address dựa vào page table và TLB.

#include <stdio.h>
int main(void) { int value=100; printf("Address: %p\n",(void*)&value); }

Địa chỉ được in là virtual address. Hai process có thể cùng dùng 0x1000 nhưng ánh xạ tới frame vật lý khác nhau. Đây là nền tảng cách ly, bảo vệ và cũng cho phép chia sẻ có kiểm soát qua shared libraries, shared memory, mmap(MAP_SHARED) và COW.

3. Page và Frame

Page là trang địa chỉ ảo; frame là khung trang vật lý. Kernel quản lý ánh xạ theo đơn vị trang thay vì từng byte. Page size phụ thuộc kiến trúc và cấu hình.

getconf PAGESIZE

Ví dụ page size 4096 byte = 212. Địa chỉ ảo 0x12345 gồm virtual page number 0x12 và offset 0x345. Nếu page 0x12 ánh xạ frame 0x8A thì physical address là 0x8A345.

Physical Address = PFN × Page Size + Offset

4. MMU, Page Table, TLB

MMU là phần cứng dịch địa chỉ và kiểm tra quyền. Page table chứa thông tin frame, present/valid, writable, user/supervisor, accessed, dirty, execute permission (tùy kiến trúc). TLB cache kết quả dịch gần đây để tránh page-table walk liên tục.

Thành phầnVai trò
MMUDịch địa chỉ và thực thi quyền
Page TableCấu trúc ánh xạ do hệ điều hành quản lý
TLBBộ nhớ đệm kết quả dịch

Thử TLB Hit / Miss

TLB mô phỏng 2 entry. Chọn page rồi bấm tra cứu nếu miss.

TLB miss có phải page fault?

Không. TLB miss có thể được xử lý bằng page-table walk nếu ánh xạ hợp lệ.

5. Stack, Heap, Data và mmap

Không gian địa chỉ process có text/executable, data/BSS, heap/brk, các mmap region, shared libraries và stack. Vị trí thực tế phụ thuộc ASLR, kiến trúc, loader và allocator.

#include <stdio.h>
#include <stdlib.h>
int global_value = 10;
static int static_value;
int main(void) {
    int local_value = 20;
    int *heap_value = malloc(sizeof(int));
    if (!heap_value) return 1;
    *heap_value = 30;
    printf("Global: %p\n", (void *)&global_value);
    printf("Static: %p\n", (void *)&static_value);
    printf("Stack : %p\n", (void *)&local_value);
    printf("Heap  : %p\n", (void *)heap_value);
    free(heap_value);
    return 0;
}

malloc có thể dùng brk, mmap, arena và cache. free trả vùng nhớ cho allocator; allocator có thể giữ lại để tái sử dụng nên RSS không nhất thiết giảm ngay.

6. Demand Paging: reserve rồi touch

Reserve/map là thiết lập vùng địa chỉ; touch là đọc/ghi thực sự. Với anonymous private mapping thông thường, ghi lần đầu có thể khiến kernel cấp physical page. malloc thành công không bảo đảm tất cả các trang đã có RAM backing riêng.

Mô phỏng 16 trang × 4 KiB = 64 KiB

Đã reserve 64 KiB
Đã touch 0 KiB
Mô hình đơn giản: giả sử mỗi trang ghi lần đầu nhận backing riêng. Thực tế có huge pages, shared mappings và các tối ưu khác.

7. Page Fault: cơ chế và chi phí

Page fault là CPU exception khi truy cập không thể hoàn tất với trạng thái mapping/quyền hiện tại. Kernel có thể cấp trang, kết nối mapping, đọc từ storage, hoặc báo truy cập bất hợp lệ (SIGSEGV/SIGBUS tùy trường hợp).

LoạiÝ nghĩaVí dụ
Minor faultKhông cần đọc nội dung trang từ storageAnonymous zero page hoặc trang đã resident
Major faultCần I/O để lấy dữ liệu trangFile-backed miss, swap-in

Minor fault vẫn có chi phí: exception, cấp trang, zero-fill, cập nhật page table và đồng bộ. Với Real-Time Linux, major faults, reclaim và cấp phát động trong vòng điều khiển có thể làm trễ deadline. Cân nhắc mlockall(), prefault, chuẩn bị working set và đo latency; không có biện pháp đơn lẻ nào bảo đảm tuyệt đối.

8. Copy-on-Write sau fork()

Sau fork(), cha và con có thể chia sẻ các physical pages private dưới dạng COW. Khi một bên ghi, kernel tách trang cần thiết. Không phải mọi trang đều dùng COW và fork vẫn có overhead metadata/page tables.

Copy-on-Write tương tác

9. VSZ, RSS và PSS

VSZ là kích thước virtual mappings. RSS là resident set size và có thể đếm trùng shared pages giữa processes. PSS chia trọng số shared pages cho các mappings.

Ví dụ A có 40 MiB private, B có 40 MiB private, chia sẻ 60 MiB: RSS(A)=100 MiB, RSS(B)=100 MiB, tổng RSS=200 MiB; PSS(A)=70 MiB, PSS(B)=70 MiB, tổng PSS=140 MiB.

ps -p 1234 -o pid,vsz,rss,comm
cat /proc/1234/smaps_rollup
cat /proc/1234/maps
cat /proc/1234/smaps

PSS là chỉ số kế toán hữu ích, không phải lượng RAM chắc chắn được giải phóng nếu kill process. smaps có overhead khi đọc.

10. Page Cache, clean/dirty và MemAvailable

Page cache giữ dữ liệu file trong RAM để lần đọc sau có thể nhanh hơn. Clean file-backed pages có thể bị reclaim rồi đọc lại. Dirty pages cần writeback thích hợp trước khi thu hồi.

free -h
               total   used   free  shared  buff/cache  available
Mem:            8Gi    3Gi   0.5Gi   0.2Gi       4.5Gi       4.2Gi

Đây là ví dụ giả định. MemAvailable ước lượng lượng bộ nhớ có thể đáp ứng thêm mà không phải swap nhiều, thường hữu ích hơn MemFree khi đánh giá tình trạng hệ thống.

11. Reclaim và độ trễ

Khi cần RAM, Linux có thể loại bỏ clean file cache, writeback dirty file pages, hoặc swap out anonymous pages nếu cấu hình cho phép. Background reclaim có thể do kswapd thực hiện; direct reclaim có thể khiến chính thread cấp phát bị trì hoãn. Scheduler cho thread chạy đúng lúc không đồng nghĩa thread không bị chặn bởi reclaim/I/O.

12. Swap và Thrashing

Swap cung cấp backing storage cho một số trang cần rời RAM. Swap partition, swap file và zram có đặc tính khác nhau. Swap không có tốc độ tương đương RAM. Thrashing là khi hệ thống dành quá nhiều thời gian paging/reclaim thay vì công việc hữu ích.

swapon --show
free -h
vmstat 1

Trong vmstat, si/so lần lượt là swap-in/swap-out. Cần xem xu hướng, latency và throughput thay vì kết luận từ một mẫu đơn lẻ.

13. OOM Killer và cgroup

Out Of Memory có thể xảy ra khi cấp phát không thể đáp ứng trong phạm vi giới hạn. OOM victim không nhất thiết là process có RSS lớn nhất. oom_score_adj và phạm vi OOM có ảnh hưởng. Container giới hạn 512 MiB có thể OOM khi cần 800 MiB dù host còn RAM.

cat /proc/1234/oom_score
cat /proc/1234/oom_score_adj
cat /sys/fs/cgroup/memory.current
cat /sys/fs/cgroup/memory.max
cat /sys/fs/cgroup/memory.events

Đường dẫn cgroup phụ thuộc cấu hình và phiên bản cgroup.

14. Lab Python: 64 MiB

Chạy Python ở terminal đầu, quan sát từ terminal khác trước và sau khi nhấn Enter. Chỉ cần khoảng 64 MiB RAM dư.

import mmap
import os

size = 64 * 1024 * 1024
area = mmap.mmap(-1, size)
print("PID", os.getpid(), flush=True)
input("Quan sát trước khi touch; Enter để tiếp tục...")
page = os.sysconf("SC_PAGE_SIZE")
for offset in range(0, size, page):
    area[offset] = 1
input("Quan sát sau khi touch; Enter để kết thúc...")
area.close()
ps -p PID -o pid,vsz,rss,comm
cat /proc/PID/smaps_rollup
free -h
vmstat 1 5
/usr/bin/time -v python3 memory_lab.py

Thay PID bằng số thực tế. Nếu không có smaps_rollup thì dùng smaps. Ví dụ trước touch VSZ=76 MiB, RSS=9 MiB; sau touch VSZ=76 MiB, RSS=73 MiB. Đây chỉ là minh họa. Với page 4 KiB, 64 MiB có 16384 trang; ghi một byte mỗi trang đủ để kích hoạt backing phù hợp.

15. Lab nâng cao bằng C

#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <sys/resource.h>
#include <unistd.h>
#define SIZE (64UL * 1024 * 1024)
static void print_faults(const char *label) {
    struct rusage usage;
    if (getrusage(RUSAGE_SELF, &usage) == 0) {
        printf("%s\n", label);
        printf("Minor faults: %ld\n", usage.ru_minflt);
        printf("Major faults: %ld\n", usage.ru_majflt);
    }
}
int main(void) {
    long page_size = sysconf(_SC_PAGESIZE);
    if (page_size <= 0) return 1;
    char *memory = mmap(NULL, SIZE, PROT_READ | PROT_WRITE,
                        MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (memory == MAP_FAILED) { perror("mmap"); return 1; }
    print_faults("Before touch");
    for (size_t i = 0; i < SIZE; i += (size_t)page_size)
        memory[i] = 1;
    print_faults("After touch");
    if (munmap(memory, SIZE) != 0) { perror("munmap"); return 1; }
    return 0;
}
gcc -O0 -Wall -Wextra memory.c -o memory
./memory

Minor fault thường tăng đáng kể, nhưng không nhất thiết đúng 16384 do tối ưu và huge pages.

17. NUMA

NUMA (Non-Uniform Memory Access): chi phí truy cập RAM phụ thuộc CPU và node chứa bộ nhớ. CPU thường truy cập local memory khác chi phí so với remote memory. Quan trọng trên server nhiều socket, HPC và database; không nhất thiết là vấn đề chính trên SBC.

numactl --hardware

18. Quy trình debug như senior

  1. Quan sát tổng thể: free -h, cat /proc/meminfo.
  2. Đo pressure: vmstat 1, cat /proc/pressure/memory.
  3. Tìm process: ps aux --sort=-rss | head, top.
  4. Đọc /proc/PID/status và /proc/PID/smaps_rollup.
  5. Tìm OOM: journalctl -k | grep -i -E 'out of memory|oom|killed process'.
  6. Ghi xu hướng theo thời gian, phân biệt leak với cache/workload hợp lệ.
  7. Dùng LeakSanitizer, AddressSanitizer, Valgrind, heap profiler hoặc Python tracemalloc phù hợp.
