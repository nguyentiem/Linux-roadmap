1. Vì sao Linux cần cây thư mục?

Linux tổ chức các tài nguyên trong một cây tên thống nhất bắt đầu tại /. Ổ SSD, thẻ SD, giao diện kernel và thiết bị đều có thể xuất hiện dưới dạng đường dẫn. Nhưng cùng là đường dẫn không có nghĩa cùng cơ chế lưu trữ.

Ví dụ: /home thường là dữ liệu bền vững; /proc/uptime được kernel cung cấp; /dev/ttyS0 có thể là cổng UART.

/
├── etc/       Cấu hình
├── usr/       Chương trình
├── var/       Log và dữ liệu thay đổi
├── home/      Dữ liệu người dùng
├── run/       Trạng thái runtime
├── tmp/       File tạm
├── dev/       Device nodes
├── proc/      Thông tin kernel/process
└── sys/       Thuộc tính thiết bị

Phản biện: Root directory / khác với home của root user /root.

2. Filesystem, partition và mount

Filesystem quản lý tên, metadata, nội dung và các thao tác với file. ext4, XFS, Btrfs là filesystem lưu trữ; tmpfs, procfs, sysfs có cơ chế khác. 
/dev/mmcblk0  (block device)
└── /dev/mmcblk0p2 (partition)
    └── ext4 (filesystem)
        └── / (mount point)

Đường dẫn không cho biết chắc dữ liệu nằm ở thiết bị nào. findmnt -T path tìm filesystem chứa đường dẫn; mountpoint path kiểm tra path có là mount point hay không.

findmnt -T /home
findmnt -T /proc/uptime
findmnt -T /dev/null

3. Mount che dữ liệu cũ

Mount filesystem mới lên thư mục có dữ liệu sẽ che dữ liệu cũ trong cây nhìn thấy, không tự xóa nó. Ví dụ trước mount /mnt/demo/original.txt, sau mount chỉ nhìn thấy nội dung của filesystem mới.

Tình huống production: service ghi dữ liệu vào /mnt/storage trước khi ổ đĩa được mount; sau khi mount dữ liệu cũ bị che. Đừng chỉ kiểm tra directory tồn tại, hãy xác nhận mount đúng.

Thử tương tác: mount / unmount
/mnt/demo/
└── original.txt

Chưa mount: thấy dữ liệu của thư mục bên dưới.

5. Đường dẫn tuyệt đối, tương đối và working directory

Đường dẫn tuyệt đối bắt đầu bằng /; đường dẫn tương đối được giải từ working directory. . là thư mục hiện tại, .. là cha. 
pwd
cd /home/user/linux-lab
cd ..
pwd
cat data.txt

Script gọi cat config.txt tìm file tương đối theo working directory của tiến trình, không mặc nhiên theo thư mục chứa script.

script_dir=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd -P)
Điều hướng mô phỏng

/home/dev/project

6. Inode, directory entry và dữ liệu

Directory entry ánh xạ tên file tới inode. Inode chứa metadata như mode, UID, GID, kích thước, timestamp, link count và thông tin truy xuất dữ liệu. Tên file thường nằm trong directory entry chứ không nằm trong inode. 
Directory /home/dev
  report.txt ──→ inode 1205 ──→ data blocks
  backup.txt ──→ inode 1205 ──→ data blocks
mkdir -p ~/linux-lab/inode
cd ~/linux-lab/inode
echo "Hello Linux" > original.txt
ls -li original.txt
stat original.txt
mv original.txt renamed.txt

Rename trong cùng filesystem thường không cần copy dữ liệu. Di chuyển giữa filesystem thường phải copy rồi xóa nguồn.

8. Hard link và symlink

Hard link là một tên khác tham chiếu cùng inode. Symlink là đối tượng riêng lưu đường dẫn đích. 
original.txt ─┐
              ├── inode 1205 ── data
hardlink.txt ─┘

symlink.txt ──(chuỗi "original.txt")──→ original.txt
echo Hello > original.txt
ln original.txt hardlink.txt
ln -s original.txt symlink.txt
ls -li original.txt hardlink.txt
rm original.txt
cat hardlink.txt
cat symlink.txt

Hard link vẫn đọc được, symlink dangling. Hard link không thể đi qua filesystem khác; symlink có thể trỏ qua filesystem khác và trỏ đến đích chưa tồn tại.

Thử xóa file gốc

original.txt: tồn tại · hardlink.txt: đọc được · symlink.txt: đọc được

9.1. Tại sao symlink bị hỏng khi đổi tên?

Symlink lưu một chuỗi đường dẫn, không giữ inode của đích. Khi đổi tên data/report.txt thành data/renamed.txt, symlink vẫn lưu chuỗi cũ. VFS giải đường dẫn cũ và nhận ENOENT. 
project/
├── data/
│   └── report.txt
└── report-link -> data/report.txt

mv data/report.txt data/renamed.txt
cat report-link
# No such file or directory

Linux không tự sửa vì đích có thể chưa tồn tại, có thể được mount sau, và một inode có thể có nhiều tên.

Mô phỏng rename và dangling symlink
project/
├── data/report.txt
└── report-link → data/report.txt

cat report-link → sample

ln -sfn data/renamed.txt report-link
# GNU ln: dùng -T nếu cần tránh dereference directory đích
ln -sfnT data/renamed.txt report-link

Phản biện: Dangling symlink không luôn là lỗi. Có thể cố ý trỏ đến đối tượng sẽ xuất hiện trong tương lai.

9.2. readlink, realpath và stat

readlink report-link
readlink -f report-link
readlink -e report-link

stat -L report-link

Symlink tương đối được giải từ thư mục chứa symlink, không từ working directory của người gọi.

10. Logical path và physical path

mkdir -p /tmp/real-project
ln -s /tmp/real-project /tmp/my-project
cd /tmp/my-project
pwd -L
pwd -P

Logical path có thể là /tmp/my-project, physical path là /tmp/real-project. pwd -L hiển thị đường dẫn logic hợp lệ; pwd -P giải symlink.

/opt/app/
├── releases/
│   ├── v1/
│   ├── v2/
│   └── v3/
└── current -> releases/v3

Đổi symlink triển khai không tự chuyển file descriptor đã mở hay tiến trình đang chạy sang binary mới.

11. /proc và procfs

/proc là pseudo-filesystem cung cấp thông tin kernel và tiến trình. /proc/uptime không phải log ghi liên tục trên SSD. 
cat /proc/uptime
cat /proc/cpuinfo
cat /proc/meminfo
cat /proc/mounts
cat /proc/self/status
ls /proc/1
ls -l /proc/self
cat /proc/uptime
    ↓ open(), read()
Linux VFS
    ↓
procfs callbacks
    ↓
Kernel tạo nội dung
    ↓
copy dữ liệu về userspace

/proc/self là magic link phụ thuộc tiến trình truy cập. Một số mục trong /proc/sys cho phép điều chỉnh kernel; không ghi tùy tiện.

12. /sys và sysfs

Sysfs biểu diễn thiết bị, bus, driver và thuộc tính kernel. 
ls /sys/class/net
cat /sys/class/net/lo/mtu
cat /sys/class/net/lo/operstate
cat /sys/class/hwmon/hwmon0/temp1_input

Ví dụ hwmon trả về 42500 có thể biểu diễn 42,5°C theo đơn vị milli-degree Celsius của thuộc tính đó. Cần kiểm tra tài liệu ABI. Sysfs phù hợp với thuộc tính và cấu hình, không nhất thiết phù hợp luồng dữ liệu tốc độ cao.

Cảnh báo: ghi vào sysfs có thể thay đổi trạng thái thiết bị hoặc phần cứng.

13. /dev và device node

Device node là đối tượng đặc biệt để userspace truy cập thiết bị qua kernel. Nó không phải chính driver. 
Application C/C++
    ↓ open/read/write
/dev/ttyS0
    ↓
VFS / TTY subsystem
    ↓
UART driver
    ↓
UART controller → TX/RX pins
ls -l /dev/null
# crw-rw-rw- ... 1, 3 ... /dev/null
ls -l /dev/ttyS0
head -c 16 /dev/zero | od -An -tx1
head -c 16 /dev/urandom | od -An -tx1

c là character device, b là block device. Major/minor xác định đăng ký thiết bị và instance theo quy ước kernel/driver. UART read có thể block tùy termios, flags và driver.

14. ls, stat, file: ba góc nhìn

ls -l report.txt
stat report.txt
file report.txt
cp /bin/ls mystery.txt
file mystery.txt

ls -l xem loại/quyền/owner/size; stat xem metadata inode; file nhận diện nội dung dựa trên dấu hiệu, không chỉ đuôi. File tên .txt vẫn có thể là ELF binary.

15. Permission denied và quyền thư mục cha

File -rw-r--r-- vẫn có thể không đọc được nếu thư mục cha drwx------ chặn người dùng. Để giải đường dẫn, tiến trình cần quyền traverse/search x trên các directory thành phần. 
namei -l /home/dev/private/report.txt

Ví dụ đời sống: có chìa khóa căn phòng nhưng không được phép đi qua hành lang. ACL, LSM (SELinux/AppArmor), mount options cũng có thể tác động.

16. File ẩn và dấu chấm

File bắt đầu bằng dấu chấm như .bashrc, .gitignore, .config được ẩn theo quy ước hiển thị. 
ls
ls -a

Dấu chấm không mã hóa file và không tự thay đổi permission. Đây không phải cơ chế bảo mật.

18. Những lỗi production tương tự

18.1. Xóa log nhưng SSD không giảm dung lượng

Tiến trình còn giữ file descriptor tới inode đã unlink.

sudo lsof +L1
df -h

18.2. df -h còn dung lượng nhưng tạo file thất bại

Có thể hết inode, quota hoặc metadata.

df -i

18.3. Docker bind mount che file image

Mount lên /app/config có thể che file cấu hình có sẵn trong image.

18.4. Release qua symlink

/opt/app/current -> releases/v3

Thay symlink có thể dùng rename atomic trong cùng filesystem, nhưng cần restart/rollout đúng cách.

18.5. Embedded Linux rootfs read-only

/usr   read-only
/etc   cấu hình theo thiết kế
/var   writable/runtime
/data  persistent partition

Tách code và dữ liệu giúp giảm ghi flash, cải thiện recovery và hỗ trợ rollback.

20. Câu hỏi nâng cao và giải thích

Tại sao rm không xóa dữ liệu ngay?

Vì unlink bỏ một tên; inode có thể còn hard link hoặc open file descriptor.

Vì sao symlink có thể trỏ sang filesystem khác?

Vì nó lưu đường dẫn, không ràng buộc cùng inode/filesystem.

Vì sao /proc và /sys không chiếm SSD như log?

Vì kernel cung cấp nội dung qua pseudo-filesystem, dù vẫn tiêu tốn tài nguyên RAM/CPU khi xử lý.

Vì sao cùng chuỗi path có thể chỉ đối tượng khác?

Do mount namespace, mount points, symlink và thay đổi directory entries.

Vì sao read() có hành vi khác nhau?

VFS thống nhất giao diện, nhưng regular file, UART, FIFO và procfs có các file operations và ngữ nghĩa I/O khác nhau.

21. Từ userspace tới phần cứng

Application
open(), read(), write(), stat()
            ↓
          Linux VFS
            ↓
    ┌───────┼────────┐
    ↓       ↓        ↓
ext4/XFS   procfs    sysfs/device interface
    ↓       ↓        ↓

Đây là sơ đồ khái niệm, không phải một đường call stack duy nhất. File object, dentry, inode và mount là các khái niệm quan trọng trong VFS.
